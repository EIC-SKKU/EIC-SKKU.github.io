# Domain migration to eic.skku.edu

The repository is prepared for `https://eic.skku.edu/`. Pushing these files
does not change SKKU's DNS or GitHub's custom-domain setting.

On October 30, 2026, public DNS still returned
`eic.skku.edu CNAME ghs.googlehosted.com`, and the domain served the older
Google Sites website. Replacing that record switches the domain to this site.
Keep the Google Sites content available until the new site has been checked.

## Repository changes

- `astro.config.mjs` uses `https://eic.skku.edu` as the production origin.
  Canonical URLs, Open Graph URLs and images, sitemaps, and RSS links derive
  from this value.
- `public/robots.txt` points to the new sitemap URL.
- Internal navigation and image paths stay relative to the site root.
- The existing GitHub Actions deployment and Pages CMS connection remain in use.

## Coordinate the switch

The repository administrator handles GitHub settings. The SKKU DNS
administrator handles the university domain's records.

1. Agree on a switch time with SKKU IT. As a preparation step, an EIC-SKKU
   organization owner can verify `eic.skku.edu` under the organization's
   **Settings → Pages → Add a domain**. Send SKKU IT the exact TXT name and
   value GitHub generates, then complete verification. Retain that TXT record.
   This verification step does not change where the website is hosted.
2. At the agreed time, open the repository's
   [Pages settings](https://github.com/EIC-SKKU/EIC-SKKU.github.io/settings/pages).
   Keep **Source: GitHub Actions**, enter `eic.skku.edu` in **Custom domain**,
   and save. Enter only the hostname, without `https://` or a trailing slash.
3. Once the domain has been saved in GitHub, have SKKU IT replace the existing
   CNAME for this hostname with the following value:

   | Field | Value |
   | --- | --- |
   | Record type | `CNAME` |
   | Host/name | `eic` in the `skku.edu` zone, or the full name `eic.skku.edu` |
   | Current target | `ghs.googlehosted.com` |
   | New target | `eic-skku.github.io` |

   Replace the existing record rather than adding a second CNAME. Use a hostname
   as the target, not a URL or repository path. Other university domains do not
   need changes. SKKU IT can use its standard TTL; a lower TTL set before the
   switch can shorten caching during the handover.
4. Wait for GitHub's DNS check and HTTPS certificate to become ready, then
   enable **Enforce HTTPS** on the same Pages settings screen. DNS propagation
   and certificate availability can take up to 24 hours. The transition may
   temporarily show different sites or certificate errors while caches update.
5. Confirm the new site and important paths below. If needed, rerun
   **Actions → Deploy to GitHub Pages → Run workflow** after saving the domain.

GitHub's documented order is to save the custom domain in Pages settings before
pointing DNS at GitHub. Coordinate those two steps closely. This repository
publishes through a custom Actions workflow, so a committed `CNAME` file is
ignored and is not required.

## Text to send SKKU IT

> Please migrate `eic.skku.edu` from Google Sites to GitHub Pages. At the agreed
> switch time, replace the CNAME target `ghs.googlehosted.com` with
> `eic-skku.github.io`. We will first configure `eic.skku.edu` as the custom
> domain in the EIC-SKKU GitHub repository. If domain verification is requested,
> we will provide the exact TXT record generated by GitHub separately.

## Verify after the switch

```sh
dig +short CNAME eic.skku.edu
# Expected: eic-skku.github.io.

curl -I https://eic.skku.edu/
curl -I https://eic.skku.edu/members/
curl -I https://eic.skku.edu/admin/
```

Check the homepage, member popups, Gallery, Publications, and the CMS button in
a browser. Confirm that `/sitemap-index.xml`, `/rss.xml`, and `/robots.txt` refer
to `https://eic.skku.edu`, and check the old GitHub Pages address for the expected
redirect after configuration.

Pages CMS itself remains at `https://app.pagescms.org/` and continues to edit
the same repository. The GPU Monitor destination also remains
`http://115.145.209.141:9000/`; moving the public website does not change its VPN
requirement.

If the switch must be rolled back, coordinate restoring the previous DNS target
with removing the custom domain from the repository's Pages settings. Revert the
origin and sitemap configuration as well if GitHub's default address becomes
the production address again.
